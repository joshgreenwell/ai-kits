## Outcome

Turn cloud/browser token gaps into evidence-backed source decisions and concrete implementation follow-ups.

## Current gap

Local transcripts do not cover every cloud task or browser chat, while account allowance movement cannot identify their exact tokens/projects.

## Acceptance criteria

1. Inspect current primary provider documentation and authorized available exports/hooks/telemetry for the specific cloud/browser surfaces in use.
2. Record a capability matrix for tokens, calls, projects, agents, tools, money, and allowances, including eligibility, identity, timestamps, data completeness, and privacy.
3. Evaluate supported cloud-to-local copies for duplicates, changed timestamps, and misclassified surface. Define how a future source would reconcile with existing local evidence.
4. Create separately bounded implementation tasks only for validated feasible sources; record inaccessible or unavailable facts and required access explicitly.
5. Keep account-wide unexplained allowance movement unattributed. No fixed quota-to-token conversion or guessed browser transcript totals.

## Verification

Deliver a dated source decision with direct references and sanitized example shapes where available. This is a feasibility task; completion must not be reported as shipped cloud collection.

Apply the common completion requirements in the [backlog index](README.md). This file is a planned task, not evidence of implementation.
